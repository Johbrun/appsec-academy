## L'en-tête dit une chose, le corps une autre

Depuis 2026-07-28, chaque POST porte `Mcp-Method` et, pour `tools/call`, `resources/read` et `prompts/get`, `Mcp-Name`. Un outil peut aussi faire recopier un paramètre en en-tête `Mcp-Param-…` grâce à `x-mcp-header`. Le but est que les répartiteurs, passerelles et WAF routent et appliquent des règles sans parser le JSON.

Le schéma est connu : deux composants, deux sources de vérité. La spécification le nomme elle-même, « un répartiteur qui route sur la valeur de l'en-tête pendant que le serveur MCP exécute selon le corps », et en tire une obligation : tout serveur qui traite le corps **doit** rejeter une requête dont les en-têtes ne correspondent pas, avec un **400** et l'erreur JSON-RPC **`HeaderMismatch` (-32020)**. Un en-tête requis manquant ou mal formé est aussi un échec. Les valeurs non ASCII arrivent encodées (`=?base64?…?=`) et se décodent avant comparaison.

<Code file="services/mcp-novafact/src/middleware/header-match.ts" hl="9,10,13,14,15">

```ts
const decode = (v: string) => {
  const m = /^=\?base64\?(.*)\?=$/.exec(v);
  return m ? Buffer.from(m[1], 'base64').toString('utf8') : v;
};
const NAMED = new Set(['tools/call', 'resources/read', 'prompts/get']);

export function headerMatch(req: Request, res: Response, next: NextFunction) {
  const body = req.body, method = req.get('mcp-method'), name = req.get('mcp-name');
  // Absent n'est pas « rien à comparer » : sinon il suffit d'omettre l'en-tête.
  const expectedName = NAMED.has(body?.method) ? (body.params?.name ?? body.params?.uri) : undefined;
  const ok = method === body?.method
    && (expectedName === undefined || (name !== undefined && decode(name) === expectedName));
  if (!ok) {
    return res.status(400).json({ jsonrpc: '2.0', id: body?.id ?? null,
      error: { code: -32020, message: 'Header mismatch' } });
  }
  next();
}
```

</Code>

Les correctifs ratés ont tous la même forme : ne comparer que si l'en-tête est présent, oublier de décoder le base64, ou comparer sans tenir compte de la casse alors que les **valeurs** sont sensibles à la casse (`Delete_invoice` n'est pas `delete_invoice`). Côté passerelle, la spécification ajoute qu'un intermédiaire qui applique une politique sur ces en-têtes devrait refuser les requêtes d'une version antérieure, où rien ne garantit que le serveur les confronte au corps. Enfin, aucun paramètre sensible ne doit être marqué avec `x-mcp-header` : un en-tête se lit et se journalise sur tout le trajet.

## Le handle n'est pas une clé

Le protocole ne garde plus d'état : un brouillon d'avoir ou un import en plusieurs étapes vit sous un **handle** émis par le serveur, que le modèle repasse en argument. La spécification le dit en une phrase, « un handle est un nom, pas une capacité » : le serveur **ne doit pas** traiter sa possession comme une authentification, **devrait** l'émettre aléatoire et le lier à l'utilisateur authentifié.

Le payload qui casse le correctif « on passe à `randomUUID()` et c'est réglé » : le handle traverse le contexte du modèle. Il apparaît dans la conversation, dans les journaux de l'hôte, dans un transcript partagé avec le support. Un collègue d'un autre tenant qui le récupère, ou une injection qui demande à l'agent d'utiliser `cn_…` vu dans un document, accède au brouillon si la clé ne contient pas l'utilisateur. Même logique pour le `requestState` des allers-retours (leçon 2) : la spécification exige de le traiter comme contrôlé par l'attaquant, de le protéger en intégrité (HMAC ou AEAD) dès qu'il influence une décision, et d'y inclure l'utilisateur, une expiration courte et l'empreinte de la requête d'origine.

## L'isolation des tenants

<Callout kind="case">
Selon BleepingComputer (18 juin 2025), Asana a prévenu ses clients qu'une « faille de logique » de son serveur MCP, active du 1er mai au 4 juin 2025, avait rendu visibles à des utilisateurs d'autres organisations des tâches, métadonnées de projets, commentaires et fichiers. Un porte-parole d'Asana a évoqué environ 1 000 clients touchés ; le serveur a été coupé, puis rétabli le 17 juin. Asana n'a pas publié de communiqué public, et le détail de la faille n'est pas connu.
</Callout>

Faute de détail, on retient les points de contrôle qu'un serveur MCP multi-tenant ajoute à ceux d'une API classique :

- **Le tenant vient du jeton**, jamais d'un argument d'outil ni d'un `_meta`, que le client remplit à sa guise (`clientInfo` est auto-déclaré).
- **Les listes peuvent varier** : la spécification permet à `tools/list` de dépendre de l'autorisation présentée. Dans ce cas, la réponse doit être marquée `cacheScope: "private"`, sinon un cache partagé la resservira à un autre tenant.
- **Les caches et index côté serveur** (embeddings, résultats de recherche, handles) portent le tenant dans leur clé.
- **Le test qui prouve le refus** : deux tenants de test, un handle et une ressource créés par l'un, appelés par l'autre, réponse identique à « inconnu ».

## SSRF : le serveur va chercher pour le modèle

Un outil qui prend une URL (importer une facture fournisseur, prévisualiser un lien) est une SSRF qu'un texte peut déclencher : l'URL vient du modèle, donc d'un document. **CVE-2026-26118** (Azure MCP Server, CVSS 8,8, corrigée au Patch Tuesday de mars 2026) est décrite par Microsoft comme une SSRF permettant à un attaquant authentifié d'élever ses privilèges ; l'avis ne détaille pas le mécanisme. La révision 2026-07-28 signale un piège moins visible : un `$ref` de schéma pointant vers une URL ne doit pas être résolu automatiquement, et si cette résolution est activée, les mêmes restrictions s'appliquent.

Sur ECS, les identifiants de la tâche sont servis par l'agent de conteneur sur une adresse link-local : aucun outil ne doit pouvoir l'atteindre. La défense (M9, leçon 11) ne change pas : liste blanche de destinations appliquée par un **proxy de sortie**, redirections revalidées, aucune résolution DNS faite deux fois. La spécification déconseille explicitement les validations d'IP écrites à la main. L'excel-mcp-server de la leçon 2 le rappelle : la traversée de chemin la plus simple devient critique dès que le serveur écoute en HTTP sans authentification.
