## Mainteneurs et confiance

**event-stream (2018)** : le mainteneur, qui ne s'occupait plus du paquet, en a confié la gestion à un inconnu qui s'était proposé. Celui-ci a ajouté une dépendance, `flatmap-stream`, dont une version contenait un code visant une application de portefeuille Bitcoin précise. Rien n'était techniquement « piraté » : la confiance a été transférée, sans que les millions d'utilisateurs en soient informés.

**xz utils (2024)**, détaillé en M13 (leçon 9), pousse la logique à l'extrême : deux ans de contributions légitimes pour obtenir les droits de publication, puis une porte dérobée présente dans les archives de release mais pas dans le dépôt Git.

La leçon défensive commune : la santé d'un projet (nombre de mainteneurs, changement de propriétaire) est un signal de risque (leçon 6), et **ce qui est construit doit être ce qui est relu** (leçon 9).

## Comptes détournés

**ua-parser-js (octobre 2021)** : le compte npm du mainteneur est détourné, trois versions publiées installent un mineur de cryptomonnaie et un voleur de mots de passe. **chalk et debug (septembre 2025)** : un e-mail imitant npm, envoyé depuis un domaine sosie, pousse un mainteneur très suivi à « mettre à jour sa 2FA » sur un faux site. L'attaquant publie des versions de 18 paquets totalisant plus de deux milliards de téléchargements hebdomadaires, avec un code qui détourne des transactions de cryptomonnaie dans le navigateur. Elles sont retirées en quelques heures.

Une 2FA par code est hameçonnable. Les réponses : clés FIDO (résistantes au phishing), aucune publication possible par simple mot de passe et code, et depuis 2026 une approbation par version (staged publishing, leçon 5).

## Pipelines compromis

**Codecov (2021)** a montré que le pipeline exécute volontiers du code tiers non vérifié (leçon 1). Les incidents suivants visent directement les workflows GitHub Actions :

- **Ultralytics (décembre 2024)** : une injection dans un workflow `pull_request_target`, combinée à l'empoisonnement du cache GitHub Actions, fait publier sur PyPI deux versions contenant un mineur. Les versions suivantes sont publiées avec un jeton d'API PyPI resté valide. La provenance, qui attestait que les deux premières venaient bien du workflow officiel, a servi à l'enquête : elle prouve **où** un paquet a été construit, pas que la construction était saine.
- **Nx « s1ngularity » (août 2025)** : un workflow ajouté quelques jours plus tôt interpole le titre des PR dans un script, sous `pull_request_target`. Le jeton de publication npm est volé ; des versions malveillantes de Nx sont publiées pendant environ quatre heures. Leur script d'installation cherche des secrets, tente d'utiliser les CLI d'assistants d'IA installées localement pour fouiller le disque, et publie le butin dans un dépôt public créé sur le compte GitHub de la victime.
- **TanStack (mai 2026)** : *pwn request*, cache empoisonné, puis le code malveillant obtient le jeton OIDC du workflow de release et publie 84 versions de 42 paquets en six minutes, malgré le trusted publishing (leçon 5).

<Callout kind="case">
**tj-actions/changed-files (mars 2025).** La chaîne commence fin 2024 : un workflow `pull_request_target` du projet SpotBugs laisse fuiter le jeton personnel d'un mainteneur, qui a aussi des droits sur le projet reviewdog. En mars 2025, l'attaquant réécrit le tag `v1` de `reviewdog/action-setup` ; cette action est utilisée, via une autre action, dans la CI de tj-actions, qui y expose son propre jeton. Le 14 mars, les tags de `tj-actions/changed-files` (utilisée par plus de 20 000 dépôts) sont redirigés vers un commit qui lit la mémoire du runner et écrit les secrets dans les logs, encodés deux fois en base64 pour échapper au masquage. Sur les dépôts publics, ces logs sont publics. La cible initiale était un projet de Coinbase. Leçons : épinglage par SHA (le seul contrôle qui neutralisait l'attaque côté consommateur), PAT remplacés par des GitHub Apps à portée limitée, et surveillance réseau des runners, qui a permis la détection.
</Callout>

## La distribution

**polyfill.io (2024)** : un service de polyfills très utilisé, chargé par `<script>` depuis son propre domaine, est racheté avec son domaine. Quelques mois plus tard, le CDN sert à certains visiteurs mobiles un code qui les redirige vers des sites frauduleux ; plus de 100 000 sites l'intègrent. La confiance accordée à un domaine se transmet à son futur propriétaire. C'est le sujet de M4 : auto-héberger ce qui peut l'être, épingler avec SRI ce qui ne l'est pas, inventorier les scripts de la page de paiement.

## Les vers : Shai-Hulud et ses vagues

| Vague | Date | Ce qui change |
| --- | --- | --- |
| Shai-Hulud | septembre 2025 | Plus de 500 paquets ; script `postinstall` qui cherche les secrets (avec TruffleHog), les publie dans un dépôt public du compte de la victime, ajoute un workflow d'exfiltration et se republie avec les jetons npm trouvés |
| Shai-Hulud 2.0 | novembre 2025 | Script `preinstall` (plus tôt, avant les contrôles), runtime Bun téléchargé pour échapper aux détections centrées sur Node ; environ 800 paquets ; machine enregistrée comme runner self-hosted pour garder un accès ; effacement de données en l'absence d'identifiants |
| « Mini Shai-Hulud » | mai 2026 | TanStack et plus de 160 paquets npm et PyPI, entrée par un workflow de release (voir plus haut) |
| CHAINDROP | août 2026 | Compte d'un mainteneur de `keyv` et de paquets voisins ; plus de 400 paquets en quelques heures ; persistance dans les dépôts via des configurations d'éditeur et d'assistant de code |

Chaque vague a répondu aux défenses de la précédente, et l'écosystème a répondu à son tour : plan de sécurisation de npm annoncé en septembre 2025, jetons classiques révoqués, trusted publishing généralisé, staged publishing (mai 2026), npm 12 et ses scripts désactivés par défaut (juillet 2026), restriction des jetons qui contournent la 2FA (août 2026).

## Ce qui se répète

- Des **références mobiles** (tags, plages de versions, domaines) là où une référence immuable était possible.
- Des **jetons longue durée et trop larges** (PAT, jetons npm, clés d'API) sur des postes et des runners.
- Des **points d'exécution implicites** : scripts d'installation, tâches d'éditeur, hooks.
- Des **workflows qui mêlent code non fiable et privilèges**.
- Une détection venue **de l'extérieur** (un chercheur, un éditeur de sécurité) en quelques minutes ou heures, d'où l'efficacité du délai d'adoption.
